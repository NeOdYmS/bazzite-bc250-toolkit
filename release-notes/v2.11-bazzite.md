# Bazzite BC250 Toolkit v2.11

**Release date:** 24 October 2026  
**Target:** AMD BC-250 / Cyan Skillfish running Bazzite (Fedora Atomic / rpm-ostree).

This release packages the current post-installation toolkit and fixes three community-reported problems. It is designed for a **test-first** configuration process rather than automatic overclocking.

## Highlights: fixes since v2.10

### #3 — NCT6687 build/install path (locally verified)

- Fixed `install_nct6687_sensors()` looking for the build output in `/opt/nct6687d/<kernel>/nct6687.ko` when the driver Makefile actually produces `/opt/nct6687d/nct6687.ko`.
- The existing installer still builds the module against the **running** kernel, installs it to `/var/lib/bc250/modules/$(uname -r)/nct6687.ko`, and enables `bc250-nct6687.service`.
- Keeps `nct6683` and `nct6687` from exposing competing Nuvoton hwmon instances for the PWM workflow.
- **Locally verified:** Bazzite 44, `7.2.9-ogc3.1.fc44.x86_64`: `nct6687.ko` compiled successfully, loaded, and the oneshot service completed with `active (exited)`.

**Remaining limitation:** changing kernels still requires rebuilding the external `nct6687` module for the new kernel; this release does **not** implement automatic rebuilds. PWM output permissions and CoolerControl mapping may require separate validation.

### #2 — Avoid a graphical-session interruption when disabling sleep (fix awaiting user testing)

- Removed the immediate `systemctl restart systemd-logind` from both `disable_sleep_modes()` and `enable_sleep_modes()`.
- Sleep/hibernate systemd targets and logind configuration are still managed, but a **reboot is requested** before relying on updated logind behavior.
- This addresses a likely source of the KDE/Steam black-screen reports. A full functional fix is **not yet confirmed** on the affected users' systems.

### #1 — CPU Governor / pipx path handling (fix awaiting user testing)

- Recognizes existing root-managed `bc250-detect` and `bc250-apply` installations even if the `pipx` management command disappeared during a Bazzite rebase.
- Uses explicit `PIPX_HOME=/var/roothome/.local/share/pipx` and `PIPX_BIN_DIR=/var/roothome/.local/bin` for root-managed installation/upgrades.
- Checks expected executables before reporting successful installation, instead of unconditionally printing success.
- Existing installations are preserved when `pipx` itself is unavailable.

**Remaining limitation:** the original issue involved an executable installed only in the user's `~/.local/bin`, and this exact user/root `PATH` case has **not yet been confirmed fixed**. Feedback is welcome on [issue #1](https://github.com/NeOdYmS/bazzite-bc250-toolkit/issues/1).

## Complete toolkit features

### Installation and guided setup

- **First Boot Check**: hardware/software preflight, current kernel and arguments, ACPI/cpufreq, sensors, available utilities, GPU/CU status, swap and active services.
- **Guided Workflow**: step-by-step setup with prompts for reboots and safety checks.
- **Bazzite / Fedora Atomic integration**: package layering through `rpm-ostree`, kernel-argument management, and systemd services.
- **Localized path detection**, including `Downloads` / `Téléchargements`.
- **Status, version/path inspection, and recovery menus.**

### Boot, storage and power management

- Plymouth/quiet boot and kernel-argument helpers.
- Btrfs-compatible swapfile setup (typical example: 32 GiB), swappiness and zswap (lz4 / adjustable pool), with status and revert functions.
- ACPI override helper that creates an early initrd containing BC250 ACPI tables.
- Optional system sleep/hibernate disabling and re-enabling, now without restarting an active logind session.

### Cooling and Nuvoton monitoring

- Build and installation flow for external `nct6687d` on the running kernel.
- NCT6686/NCT6687 sensor detection, fan RPM/temperature inspection and hwmon conflict checks.
- Works alongside external fan-control software such as CoolerControl when the kernel module exposes the required PWM interfaces; it does not replace CoolerControl.

### CPU and GPU tuning

- **CPU:** `bc250_smu_oc` integration, `bc250-detect` stability/throttling tests, frequency/VID/temperature inputs, temporary test/keep options, `overclock.conf` review and optional boot-time `bc250-apply` service.
- **GPU:** integration with `cyan-skillfish-governor-smu`, editable frequency and thermal-governor configuration, service controls and logs.
- Performance profiles and manual tuning workflow; no preset is universally stable across boards.

### 40 CU management

- `umr` and `bc250-cu-live-manager` integration for optional runtime 40 CU routing.
- Live apply, interactive manager/status, save boot restore table, restore stock live and uninstall boot restore service.
- **Use live testing and stress testing before enabling a persistent 40 CU state.**

### Diagnostics and rollback

- Sensor watch, CPU/GPU governor journals, `amdgpu_top` (including Distrobox helpers), GPU sysfs diagnostics, service status, `btop`/system monitors.
- Revert options for governor settings, swap/zswap and kernel arguments, and re-enable sleep when desired.
- Existing Fedora Atomic deployment rollback mechanisms remain available.

### Issue follow-up

A repository GitHub Actions workflow monitors [#1](https://github.com/NeOdYmS/bazzite-bc250-toolkit/issues/1), [#2](https://github.com/NeOdYmS/bazzite-bc250-toolkit/issues/2), and [#3](https://github.com/NeOdYmS/bazzite-bc250-toolkit/issues/3) for replies after the v2.11 fix notifications. After 30 days with no participant reply it can comment and close the issue; a user reply keeps it open.

## Install or update

**Fresh install:**
```bash
git clone https://github.com/NeOdYmS/bazzite-bc250-toolkit.git
cd bazzite-bc250-toolkit
sudo bash ./bc250-toolkit-bazzite.sh
```

**Update an existing checkout:**
```bash
cd ~/Documents/Github/bazzite-bc250-toolkit
git pull --ff-only origin main
sudo bash ./bc250-toolkit-bazzite.sh
```

If a kernel update has invalidated a previous `nct6687.ko`, use **Initial Setup → NCT6687 Sensors** to rebuild for the new running kernel. Make sure matching kernel development files are present.

## Testing and compatibility

- **Confirmed locally:** Bazzite Deck 44 (2026-10-23), Linux `7.2.9-ogc3.1.fc44.x86_64`; fixed NCT6687 compile/load path and systemd service.
- **Static checks:** `bash -n` and `git diff --check` passed for the three fixes.
- **Community validation pending:** the precise #1 user-local executable/PATH case and graphical-session behavior reported in #2.
- CPU voltage/frequency changes, 40 CU routing, kernel arguments and thermal limits can destabilize the system. Test incrementally and keep a rollback path.
